# About Us and Contact Admin

Added locally on 24 October 2026. This note is not a deployment receipt.

- `/about` is public and linked from the shared footer. It describes the capstone, implemented features, team, and limits of recommendations. The supplied group photo is at `public/about/xlore-u-team.png`; names are listed collectively, not matched to faces. Background and names were checked against the supplied XLORE U PAPER.
- `/contact` is linked as **Contact Admin** in the footer for students and institutions. Verified signed-in users enter their name (2–100 characters, letters/spaces), contact email (up to 190 characters), and message (10–3,000 characters). Account name/email are editable defaults. **My conversations** lists only that account's requests. Open one to read the original message and administrator replies, load earlier replies, and continue the conversation. Replies are 1–3,000 characters. Signed-out visitors see student/institution sign-in options; sign-in preserves a selected contact conversation.
- `/admin/messages` is a private inbox in the admin sidebar. Search names, contact/account email, account name, or original message text; filter new/read/closed; paginate; and change status. **View conversation & reply** opens the private reply composer. Conversations are sorted by latest activity. Reading a page does not automatically mark messages read. Submitted contact email is labeled separately from the signed-in account email.

Messages are saved to the backend, not opened in a local email app. Admin replies produce an in-app bell notification for the account that started the conversation. Selecting it opens `/contact?thread=<id>` to read and reply; a typed contact email does not grant access or receive notifications. An account reply marks the conversation New (including a previously closed one) and notifies only verified administrators already participating in that conversation. An admin reply marks it Read. Neither sends email, and no guaranteed response time is promised. Existing bell polling/refresh controls apply; this is not a websocket or push service. The administrator's sign-in email is not published as a contact address. These are private support messages, not school posts. Notification previews do not contain message text or contact emails. The Privacy Policy discloses the collected fields.

Successful sends show confirmation. Failed sends preserve the draft. A per-draft request ID avoids duplicate records and repeat notifications when an unchanged send is retried. Unsaved navigation protection applies to new messages and replies; switching accounts or conversations cannot display a previous account's draft. Reply reads use 30-item keyset pages and an earlier-replies control; fresh loads return the latest page while previously loaded replies remain merged and deduplicated.

## Rollout and checks

Requires matching backend API and migrations `030_contact_messages.sql` and `031_contact_conversations.sql` before deployment. The reply extension is not deployed by these edits. Migration 031 preserves original support requests and notification read states, adds private replies, and extends notification references; deploy the backend after applying it, then the frontend. Confirm and back up the intended database before running the backend migration runner. No new secrets or public support address are required. Existing accounts, assessments, and schools are untouched. Without coordinated backend rollout and migrations, conversation reads/notifications cannot work.

Run `npm test`, `npm run check`, and `npm run build`. Backend authorization, validation, search, retry, audit and rate-limit tests are described in the matching backend guide. A visual browser check remains necessary if the preview tool is unavailable.
